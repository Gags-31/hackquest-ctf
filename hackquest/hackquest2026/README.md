# HACKQUEST CTF 2026 — Complete Event Platform

**Organisers:** Pragyan × IEEE-CS KLEIT Chapter  
**Tagline:** BREAK THE TARGET. OWN THE FLAG.  
**Event date:** 25 November 2026, 11:00 IST (explicitly configured, never derived from deployment time)  
**Live deployment:** https://hackquest-2026.vercel.app

A full-stack, server-authoritative CTF platform: React/TypeScript/Tailwind SPA + FastAPI + SQLAlchemy.
It contains four rounds, 48 original challenges, 20 cyber riddles, meme breaks, team registration
with 2–4 members, cryptographically generated team access codes, hint system, flag validation,
scoring, synchronized round control, an organiser-only live scoreboard, exports and audit logs.

## Architecture

```
hackquest2026/
├── api/index.py          # Vercel ASGI entry point
├── backend/app/          # FastAPI application
│   ├── content.py        # 48 challenges, 20 riddles, memes, schedule
│   ├── seed.py           # idempotent database seeding
│   ├── models.py         # normalized schema
│   └── routers/          # public, auth, team, admin
├── frontend/             # React + TypeScript + Tailwind SPA (dist/ is built)
├── tests/                # 25 acceptance tests → 26 verification cases
└── docs/                 # manuals and deployment notes
```

## Quick start (local)

```powershell
cd hackquest2026
python -m pip install -r requirements.txt
cd frontend; npm install; npm run build; cd ..
$env:DATABASE_URL = "sqlite:///./backend/hackquest2026.db"
$env:SECRET_KEY = "local-dev-secret"
python backend/cli.py seed
python -m uvicorn app.main:app --app-dir backend --port 8000
```

Open `http://localhost:8000`.

## Tests

python -m pytest backend/tests -q

## Credentials

Two independent organiser accounts are created at seed time:

| Username | Role |
|---|---|
| `pragyan_lead` | Primary organiser |
| `ieee_lead` | Co-organiser |

Passwords are **never stored in source**. They are supplied through `ORG1_PASSWORD` /
`ORG2_PASSWORD` environment variables or generated by `python backend/cli.py organizers`.
Both accounts are forced to change their password on first login via `/change-password`.

## Security notes

- Flags and solutions are returned **only** by `/api/admin/challenges`, which requires an organiser session.
- Participant APIs never include `flag`, `solution`, or `concept` fields.
- Teams cannot start, pause or reset rounds; only organisers can.
- Access codes are `HQ-XXXXXX`, generated with `secrets`, unique by DB constraint, and revocable.
- Flag submissions are rate-limited and compared in constant time.
- All challenge data is synthetic, fictional and authorised; no real targets are used.

## Deployment

See `docs/DEPLOYMENT.md`. The Vercel deployment serves the SPA and API from a single function.
For a real event, attach a persistent PostgreSQL database via `DATABASE_URL` — the default
Vercel SQLite file is ephemeral.
